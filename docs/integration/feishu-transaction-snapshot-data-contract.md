# 飞书供应商交易月度快照数据契约

版本：v1.1
生效日期：2026-08-28
状态：开发测试有效

## 1. 范围与边界

表名固定为 `供应商交易月度快照`，用于保存按月聚合的采购、收货、合同和结算数据，为后续商务、质量和交付风险分析提供输入。

- 主数据、供货能力和联系人仍遵循《飞书供应商三表数据契约》，并保持只读同步。
- 本表中的 `data_mode=synthetic` 记录只能用于开发、演示和回归测试；不得进入正式风险评分、正式告警或采购建议。
- SuppliSense 的线上服务不提供飞书写接口。开发测试写入只能通过 `backend/scripts/seed_feishu_transaction_snapshot.py --confirm-test-write` 显式执行。

## 2. 关联与唯一性

关联键为 `供应商代码`，必须匹配供应商主数据表中的业务代码。

月度聚合记录的业务唯一键为：

```text
统计月份 + 供应商代码 + 采购组织代码 + 基地 + 物料号 + 计量单位 + 币种
```

如果需要区分同月同物料的多份合同，应额外使用 `合同编号`。`快照ID` 是同步、去重和审计使用的稳定文本键，推荐由导入转换或测试脚本生成。

## 3. 字段与最小口径

模板文件：`outputs/feishu-transaction-template-20260828/供应商交易月度快照-飞书导入模板.xlsx`。

飞书从空 Excel 模板导入时可能默认将所有列识别为文本。开发测试可以由灌入脚本按真实字段类型序列化数据；进入正式风险计算前，数量和金额列必须改为数字类型，`统计月份`、`快照日期` 和 `更新时间` 必须改为日期或日期时间类型。

必填核心字段：

- `快照ID`、`统计月份`、`快照日期`
- `供应商代码`、`供应商名称`、`采购组织代码`、`基地`
- `物料号`、`物料名称`、`计量单位`
- `收货数量`、`正结算数量`、`负结算数量`、`实结算数量`、`已结算数量`、`未结算数量`
- `单价`、`币种`、`金额口径`、`合同状态`
- `收货金额`、`实结算金额`、`已结算金额`、`未结算金额`
- `数据来源`、`数据模式`、`更新时间`

`负结算数量` 推荐保存为负数，满足：

```text
实结算数量 = 正结算数量 + 负结算数量
实结算数量 = 已结算数量 + 未结算数量
实结算金额 = 已结算金额 + 未结算金额
```

金额比较必须同时满足币种和含税口径一致。不同物料或计量单位的收货数量不得直接汇总。

## 4. 配置

四张表共用同一飞书应用和 `FEISHU_BITABLE_APP_TOKEN`。交易月度快照使用：

```text
FEISHU_BITABLE_TRANSACTION_TABLE_ID
```

该变量只保存 table ID；真实应用凭据只能留在本地 `.env`，不得提交到仓库。

## 5. 只读同步与数据质量隔离

运行时由既有 `POST /api/v1/sourcing/suppliers/sync` 统一读取四张飞书表，并在本地保存到
`supplier_transaction_snapshots`。服务端不调用任何飞书创建、更新或删除接口。

- 未配置 `FEISHU_BITABLE_TRANSACTION_TABLE_ID` 时，交易表被跳过，既有三表同步不受影响。
- 每条快照按 `source + source_record_id` 幂等更新，批次中未再次读取到的记录会被标为 `stale`。
- 空 Excel 导入导致的文本数值可被安全解析；无法解析的数值、缺少核心字段、结算恒等式不平衡都会保留在本地，并写入 `validation_errors` 或 `data_quality_issues`。
- 仅同时满足 `data_mode=real`、`data_quality_status` 无错误、`sync_status=current` 的记录可进入正式商务风险 P0。`synthetic`、`unknown`、`invalid` 数据只可用于开发、演示和回归。
- 当前正式启用的是“供应依赖与可替代性”子维度。合同状态、未结算暴露、价格变化只作为观察信号展示，不生成完整商务风险分数或正式告警。
- 开发演示可设置 `BUSINESS_RISK_DEMO_ENABLED=true`；该开关还必须同时满足 `DEBUG=true` 才生效。启用后，P0 会在没有真实快照时读取校验通过的 `synthetic` 快照，并返回 `assessment_data_mode=demo`、`decision_usable=false` 和不可用于正式决策的限制。生产或未启用演示开关时，`synthetic` 始终被隔离。

## 6. 开发测试数据灌入

在 `backend` 目录执行：

```bash
python scripts/seed_feishu_transaction_snapshot.py --confirm-test-write
```

脚本会先读取飞书字段并校验模板字段，再读取最多三家已有供应商作为关联对象，最后创建 12 条固定 `SYN-TXN-V1` 前缀的合成记录。重复运行会按 `快照ID` 跳过已有记录。
