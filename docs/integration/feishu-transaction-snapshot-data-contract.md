# 飞书供应商月度交易数据契约

版本：v2.0

生效日期：2026-09-07

状态：比赛真实数据契约

## 1. 业务范围

活动交易表按“供应商 × 年月”保存内部采购月度汇总，用于给供应商风险复核补充采购敞口证据。它不能单独证明供应商自身风险、交付风险、价格风险或可替代性。

飞书表 ID 由 `FEISHU_BITABLE_TRANSACTION_TABLE_ID` 配置。运行时只读取飞书，标准化结果保存到 MongoDB 的 `supplier_transaction_snapshots`。

## 2. 记录粒度与唯一键

每条记录代表一家供应商在一个自然月的汇总：

```text
供应商代码 + 年月
```

该组合必须唯一。同步发现重复组合时，会拒绝整个交易表批次，避免重复计算采购敞口。

## 3. 必填字段

| 字段 | 飞书类型 | 定义 |
|---|---|---|
| 供应商代码 | 文本 | 与供应商主数据一致的业务代码；使用文本以保留前导零 |
| 供应商名称 | 文本 | 供应商全称 |
| 年月 | 数字或文本 | `YYYYMM`，同步后统一保存为 `YYYY-MM` |
| 收货记录数 | 数字 | 原始明细去重后，`收货数量 > 0` 的明细行数；必须为非负整数 |
| 实结算金额 | 数字 | 源采购数据中的月度实结算金额；允许为负数 |

`收货记录数` 不代表收货数量、送货批次或交付频次。负实结算金额可能是冲销或调整，只作为复核线索，不直接判定为风险。

## 4. 数据模式与审计字段

飞书业务表保持五个字段。以下元数据由同步服务补充，不要求用户维护：

- `data_granularity=supplier_month`
- `data_source=feishu_supplier_monthly_summary`
- `source_record_id`
- `synced_at`
- `sync_batch_id`
- `sync_status`

数据模式通过环境变量显式声明：

```text
FEISHU_BITABLE_TRANSACTION_DATA_MODE=real
```

未声明或值为 `unknown` 时，记录不会进入正式分析。`synthetic` 仅允许在 `DEBUG=true` 且显式启用演示模式时使用。

## 5. 数据质量规则

- `供应商代码` 必须能关联当前供应商主数据。
- `供应商代码 + 年月` 不得重复。
- `年月` 必须能解析为有效自然月。
- `收货记录数` 必须是非负整数。
- `实结算金额` 必须是可解析数字，允许为零或负数。
- 月份缺失与数值为零严格区分；缺失月份不按零参与趋势计算。
- 同月实结算金额占比只在已成功关联的供应商范围内比较，结果必须披露该限制。

## 6. 当前可输出指标

- 最新月实结算金额、收货记录数。
- 同月已关联供应商中的正向实结算金额占比。
- 相邻自然月均存在时的金额和记录数环比。
- 最近 12 个自然月的金额、记录数和数据完整度。
- 负结算月份、收货记录为零但仍有结算的月份。

当前不输出品类集中度、单一来源判断、交付频次、价格变化、未结算比例或完整商务风险评分。

## 7. 旧物料级契约兼容

标准化器仍可读取历史物料级交易快照，供旧测试和定向回归使用。活动比赛数据只使用本文件定义的供应商月度汇总表，旧表不再作为活动交易数据源。
