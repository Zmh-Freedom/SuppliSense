# 飞书供应商三表数据契约

版本：v1.0
生效日期：2026-08-27
状态：当前有效契约
适用范围：SuppliSense 读取飞书多维表格中的正式供应商主数据、供货能力和联系人信息。

## 1. 契约目标

飞书多维表格是正式供应商主数据的临时权威来源，SuppliSense 只读同步并保存本地快照。供应商库、智能寻源和风险监控必须基于同一套供应商身份和字段语义。

本契约解决以下问题：

- 固定三张表的名称、字段、类型和必填规则；
- 固定 `supplier_code`、`supplier_id` 和 `source_record_id` 的职责；
- 固定主表、能力表和联系人表的关联方式；
- 固定空值、枚举、更新时间、失效和异常处理规则；
- 为后续只读同步、校验和自动化测试提供唯一依据。

## 2. 数据边界

| 数据 | 权威来源 | SuppliSense 用途 | 是否写回飞书 |
|---|---|---|---|
| 供应商名称、代码、状态、工商基础信息 | 供应商主数据 | 正式供应商识别、检索和展示 | 否 |
| 品类、产品、工艺、区域和能力状态 | 供应商供货能力 | 供应商推荐和匹配 | 否 |
| 联系人、电话、邮箱和验证状态 | 供应商联系人 | 推荐结果卡片和后续联系参考 | 否 |
| 风险、舆情、ESG、合规和监控任务 | SuppliSense 本地数据库 | Agent 分析、历史和告警 | 不适用 |
| 联网或第三方发现的外部候选 | 外部数据源 | 候选推荐和身份核验 | 否 |

当前系统不通过飞书执行供应商准入、主数据编辑、供应商注册或任何回写操作。

## 3. 表和关联规则

### 3.1 供应商主数据

表名固定为 `供应商主数据`。一家公司一行。

| 字段 | 飞书类型 | 必填 | 规则 |
|---|---|---:|---|
| 供应商代码 | 文本 | 是 | 业务系统供应商代码；表内唯一；去除首尾空格后保存 |
| 供应商名称 | 文本 | 是 | 企业全称；不得使用纯简称 |
| 供应商简称 | 文本 | 否 | 常用简称 |
| 统一社会信用代码 | 文本 | 建议 | 18 位代码；未知时留空，不填虚构值 |
| 供应商状态 | 单选 | 是 | `正常`、`暂停合作`、`禁止合作`、`已淘汰`、`候选` |
| 所属行业 | 多选 | 否 | 使用统一行业名称 |
| 主要产品 | 多行文本 | 是 | 产品名称或型号，多个值用换行或逗号分隔 |
| 经营范围 | 多行文本 | 否 | 工商或业务维护的经营范围 |
| 公司网址 | URL | 否 | 完整 `http://` 或 `https://` 地址 |
| 注册地址省份 | 单选 | 否 | 省级行政区标准名称 |
| 注册地址城市 | 文本 | 否 | 城市标准名称 |
| 注册地址 | 多行文本 | 否 | 详细地址 |
| 成立日期 | 日期 | 否 | `YYYY-MM-DD` |
| 法定代表人 | 文本 | 否 | 法定代表人姓名 |
| 是否上市 | 单选 | 否 | `是`、`否`、`未知` |
| 母公司名称 | 文本 | 否 | 没有母公司时留空 |
| 母公司统一社会信用代码 | 文本 | 否 | 有母公司且可获得时填写 |
| 数据更新时间 | 日期时间 | 是 | 来源数据最后更新时间，不是同步时间 |
| 备注 | 多行文本 | 否 | 人工补充说明，不作为结构化筛选条件 |

### 3.2 供应商供货能力

表名固定为 `供应商供货能力`。一个供应商可以有多行，每个品类或产品能力独立一行。

| 字段 | 飞书类型 | 必填 | 规则 |
|---|---|---:|---|
| 供应商代码 | 文本 | 是 | 必须匹配主数据中的唯一供应商代码 |
| 品类 | 文本 | 是 | 使用标准品类名称；一个主要品类一行 |
| 产品名称 | 文本 | 是 | 具体产品或产品族 |
| 产品关键词 | 多行文本 | 否 | 用逗号分隔，用于检索扩展 |
| 工艺能力 | 多行文本 | 否 | 生产、加工或研发能力 |
| 是否具备设计开发能力 | 单选 | 否 | `是`、`否`、`未知` |
| 供货区域 | 多选 | 否 | 使用统一区域名称 |
| 生产地 | 文本 | 否 | 工厂城市或地区 |
| 产能说明 | 多行文本 | 否 | 产能、交付周期和交付能力说明 |
| 相关资质概况 | 多行文本 | 否 | 与该能力相关的资质摘要 |
| 能力状态 | 单选 | 是 | `已验证`、`待验证`、`已失效` |
| 更新时间 | 日期时间 | 是 | 该能力记录最后更新时间 |

### 3.3 供应商联系人

表名固定为 `供应商联系人`。一个供应商可以有多名联系人。

| 字段 | 飞书类型 | 必填 | 规则 |
|---|---|---:|---|
| 供应商代码 | 文本 | 是 | 必须匹配主数据中的唯一供应商代码 |
| 联系人姓名 | 文本 | 是 | 不得使用“无”或虚构占位值 |
| 职务 | 文本 | 否 | 联系人职务 |
| 联系人类型 | 单选 | 是 | `商务`、`技术`、`质量`、`财务`、`其他` |
| 电话 | 电话 | 否 | 可公开使用的联系电话；无则留空 |
| 邮箱 | 文本 | 否 | 工作邮箱；格式错误时标记无效 |
| 是否主要联系人 | 单选 | 是 | `是`、`否`；同一供应商最多一个主要联系人 |
| 是否已验证 | 单选 | 是 | `是`、`否`、`未知` |
| 验证时间 | 日期时间 | 否 | 最近一次联系方式验证时间 |
| 备注 | 多行文本 | 否 | 联系偏好和补充说明 |

## 4. ID 和身份规则

| 标识 | 来源 | 作用 | 可变性 |
|---|---|---|---|
| `supplier_code` | 飞书主数据业务字段 | 三张表的关联键和业务展示字段 | 业务上应保持不变；变更需人工治理 |
| `supplier_id` | SuppliSense 首次同步生成 | 平台内部稳定主键，供推荐、风险和监控历史引用 | 不可变 |
| `source_record_id` | 飞书 API `record_id` | 同步幂等、来源追踪和原始记录定位 | 由飞书管理 |
| `candidate_id` | SuppliSense 外部发现流程 | 外部候选临时标识 | 不得当作 `supplier_id` |

正式供应商的映射键为：

```text
source_system + source_record_id -> supplier_id
supplier_code                  -> 主数据、能力表、联系人表关联
```

如果主数据中出现相同 `supplier_code` 的多条记录，整批同步不得报告为成功；该批次必须进入错误或人工复核状态。

## 5. 值、空值和时间语义

- 空值统一保存为 `null` 或空集合，不使用“无”“暂无”“未知未知”等自由文本代替结构化空值。
- `未知` 表示已确认该字段暂时无法判断；空值表示来源没有提供该字段，两者不能混用。
- 单选和多选值必须使用契约中定义的枚举；未识别值不得静默转换为正常状态。
- 字符串同步前去除首尾空格；中文逗号和英文逗号均可作为列表分隔符，落库后统一为数组。
- `数据更新时间`、能力表的 `更新时间` 和联系人表的 `验证时间` 是业务时间；`synced_at` 是平台同步时间，两者分开保存。
- 业务时间无法解析时保留原始值并标记该字段无效，不得用当前时间伪造来源更新时间。
- 主数据状态映射到本地状态：`正常 -> active`、`暂停合作 -> suspended`、`禁止合作 -> blocked`、`已淘汰 -> deprecated`、`候选 -> prospective`。

## 6. 同步和异常规则

1. 三张表分别读取、分别标准化，并携带同一同步批次 ID。
2. 主表先完成身份索引，再校验能力表和联系人表的 `供应商代码`。
3. 能力表或联系人表中的孤儿记录跳过关联，但必须计入 `skipped` 并记录告警。
4. 单条字段格式错误不应导致其他合法记录丢失；必填字段错误的记录不得进入正式快照。
5. 同一 `source_record_id` 重复同步必须更新原快照，不得产生重复记录。
6. 成功批次未返回的历史记录标记为 `stale`，不直接物理删除。
7. 任一表请求失败时，批次状态为 `partial_failed` 或 `failed`，不得伪装为完整成功；查询端使用最近一次有效快照并展示数据过期状态。
8. 未配置飞书或飞书功能关闭时，可以回退本地供应商库，但响应必须能区分数据来源。
9. 任何同步异常必须包含表名、批次 ID、来源记录 ID（如有）和可读错误信息。

## 7. 本地标准化快照建议结构

主数据快照至少包含：

```json
{
  "supplier_id": "supplier-...",
  "supplier_code": "8110023",
  "name": "深圳市康斯得电子有限公司",
  "source_system": "feishu_bitable",
  "source_record_id": "rec...",
  "status": "active",
  "source_updated_at": "2026-08-25T10:00:00+08:00",
  "synced_at": "2026-08-27T10:00:00+08:00",
  "sync_status": "current"
}
```

能力和联系人记录通过 `supplier_id` 关联，同时保留 `supplier_code` 和各自的 `source_record_id`，便于审计和重新同步。

## 8. 契约验收

实现三表同步前必须具备以下自动化测试：

- 三张表的正常记录可以标准化；
- 主数据缺少供应商代码或名称时被跳过并计数；
- 重复 `supplier_code` 被拒绝；
- 能力表、联系人表孤儿记录被识别；
- 枚举、日期、邮箱和 URL 的非法值按规则处理；
- 重复同步同一 `source_record_id` 不产生重复快照；
- 空表、分页、部分失败和历史记录 stale 场景可验证；
- 关闭飞书或同步失败时可回退本地数据，并明确返回来源状态。

CSV 建表模板位于 `outputs/feishu_supplier_template/`，字段发生变更时必须先修改本契约，再同步模板、适配器和测试。

## 9. 配置约定

三张表使用同一个飞书自建应用和 `FEISHU_BITABLE_APP_TOKEN`，通过以下环境变量分别指定：

```text
FEISHU_SUPPLIER_MASTER_TABLE_ID       # 供应商主数据
FEISHU_SUPPLIER_CAPABILITY_TABLE_ID   # 供应商供货能力
FEISHU_SUPPLIER_CONTACT_TABLE_ID      # 供应商联系人
FEISHU_SUPPLIER_ASSIGNMENT_TABLE_ID   # 供应商责任分配（采购员、科室、采购经理）
```

三张表均必须分别配置对应的 table ID；不再支持旧的单表配置变量。三表同步启用前必须完成三项配置。
