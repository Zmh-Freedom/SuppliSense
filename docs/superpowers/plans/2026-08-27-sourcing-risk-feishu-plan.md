# 供应商推荐、风险监控与飞书只读数据源实施计划

日期：2026-08-27
状态：当前唯一有效计划，实施中
适用分支：`codex/feishu-bitable-readonly` 及其后续功能分支

## 1. 目标与边界

将 SuppliSense 收敛为面向采购人员的供应商推荐与风险监控 Agent：从飞书多维表格读取正式供应商主数据，结合历史数据、外部数据和证据完成推荐与风险分析，并通过人工确认执行“加入监控”等有限本地动作。

### 1.1 当前范围

- 供应商主数据：飞书多维表格只读同步；平台保存本地快照用于查询、缓存和审计。
- 智能寻源：按品类、产品、区域、能力和资质发现并排序供应商。
- 风险监控：对正式供应商和已识别候选执行风险、舆情、合规等分析与持续监控。
- Agent：支持多轮上下文、供应商引用、证据补全、结果校验、受控 Loop 和可恢复执行。
- 人工确认：仅对加入监控、创建监控任务等本地业务写操作显示审批卡片。

### 1.2 明确不在当前范围

- 不在 SuppliSense 中执行供应商准入、供应商注册、主数据编辑或回写飞书。
- 不把外部联网候选自动写入正式供应商主数据。
- 不把风险评估结果、Agent 推荐记录和运行轨迹写回飞书。
- 不以增加子 Agent 数量为目标；统一 Supervisor、Worker、证据和校验协议。
- 知识库文档上传、文件解析和本地向量检索已移出当前范围；供应商/预警业务 Excel 导入仍保留。

## 2. 当前基线

以下能力已经存在，本计划只在其上继续收敛，不重复建设：

- LangGraph ReAct、Plan-Execute、Supervisor 和统一会话状态。
- 供应商引用保持、多企业多维度任务矩阵和受控 Loop。
- 风险、ESG、舆情、合规工具及证据安全状态。
- 人工审批、SSE 工作流、Trace、恢复和 E2E 验收基础设施。
- 前端 AI 工作台、智能寻源、风险监控和供应商库边界调整。
- 飞书 Bitable 单表只读客户端、供应商快照、字段标准化和失败回退。

## 3. 目标架构

```text
飞书 4 张业务表
  -> Feishu Read-only Sync
  -> Supplier Snapshot + supplier_id 映射
  -> 历史本地数据 / 飞书快照 / 联网发现
  -> Candidate Normalizer + Identity Resolver
  -> Task Matrix Planner
  -> Sourcing Worker 或 Risk/ESG/Sentiment/Compliance Worker
  -> Evidence Completion Loop
  -> Result Validator Loop
  -> Evidence Merger + Decision Builder
  -> 推荐结果 / 风险结论 / 人工确认卡
```

### 3.1 数据归属

| 数据 | 权威来源 | 平台用途 |
|---|---|---|
| 供应商代码、名称、状态 | 飞书供应商主数据 | 业务检索和正式供应商识别 |
| 产品、品类、能力、区域 | 飞书供应商供货能力 | 推荐匹配 |
| 电话、邮箱、官网 | 飞书供应商联系人及主数据 | 结果卡片展示 |
| 月度采购、收货、合同、结算 | 飞书供应商交易月度快照 | 商务风险 P0 的供应依赖信号与观察证据 |
| 外部候选 | 联网/第三方数据源 | 暂存、去重、待验证，不进入正式主数据 |
| 风险事件、评估、证据、监控任务 | MongoDB/PostgreSQL | Agent 分析、历史和审计 |

### 3.2 身份规则

- `supplier_code` 是业务人员使用的供应商代码，展示和搜索优先使用它。
- `supplier_id` 是平台内部不可变标识，由首次同步时生成并持久化。
- `source_system + source_record_id` 用于飞书同步幂等和映射恢复。
- 外部候选使用 `candidate_id`；未完成确定性身份匹配前不得当作 `supplier_id`。
- 风险、监控和推荐历史引用 `supplier_id`；界面展示 `supplier_code + supplier_name`。

## 4. 实施任务

### Task 1：冻结飞书三表数据契约（P0）

- [x] 固化 `供应商主数据`、`供应商供货能力`、`供应商联系人` 的字段、类型、必填规则和枚举值。
- [x] 明确 `supplier_code`、`supplier_id`、`source_record_id` 的映射规则。
- [x] 确认空值、未知、无效、已验证和更新时间的统一语义。
- [x] 将字段契约与 CSV 模板、README 和适配器别名保持一致。

说明：正式契约已写入 `docs/integration/feishu-bitable-data-contract.md`，CSV 模板和 README 已同步；适配器别名及三表标准化将在 Task 2 实现，避免在契约冻结阶段混入同步逻辑改造。

验收：业务人员可以按字段说明创建飞书三表；同一供应商的子表记录可以通过 `supplier_code` 稳定关联。

### Task 2：完成飞书多表只读同步（P0）

- [x] 增加供应商主数据、供货能力和联系人三张表的独立配置。
- [x] 实现三张表的独立分页读取。
- [x] 对主数据、能力、联系人分别保存标准化快照和来源记录 ID。
- [x] 同步过程保持幂等，支持重复同步、空表、字段缺失和部分失败。
- [x] 明确同步批次、更新时间、过期记录和本地回退策略。
- [x] 禁止任何飞书写 API；同步失败不得伪装为成功。

实施记录：三张表独立读取并共享 `batch_id`；主数据先建立 `supplier_code -> supplier_id` 映射，再关联能力和联系人快照；成功读取的表才允许写入和标记历史记录 `stale`。表结构错误、读取失败或主数据代码重复时阻止对应表提交，错误明细统一包含表名、批次 ID、来源记录 ID（如有）和原因；四张表的可选交易快照继续复用同一只读批次。

验收记录：飞书适配器、供应商库和寻源定向回归 33 项通过；Python 编译检查和 `git diff --check` 通过。真实 PostgreSQL/MongoDB/Redis 集成测试未在本阶段执行。

验收：三表同步后，供应商库、寻源和风险目标解析使用同一正式供应商身份；重复同步不产生重复供应商。

### Task 3：收敛智能寻源链路（P0）

- [x] 固定查找顺序：历史/本地数据 → 飞书正式供应商快照 → 天眼查和联网发现。
- [x] 统一品类、产品关键词、区域、能力和资质的匹配规则。
- [x] 外部候选保留 `candidate_id`、来源、联系方式、身份状态和证据。
- [x] 推荐结果展示匹配原因、来源、更新时间、官网和可用联系方式。
- [x] 无结果、调用失败、数据不足和候选待验证必须分别反馈。
- [x] 当前阶段只允许推荐和加入监控，不输出或执行准入动作。

实施记录：寻源发现固定本地/历史与飞书正式快照优先、外部天眼查和联网补充的顺序；统一品类、产品、区域、能力和资质的匹配族规则；外部候选保留 `candidate_id`、来源、联系方式、身份状态、更新时间和证据。发现服务增加本地查询失败、天眼查/联网阶段失败和联系方式补采失败的可恢复边界；已有候选不会被空补采结果覆盖；结果增加 `local_status`、`local_failure_reason`、`external_failure_reasons` 和 Loop 失败阶段，供 Agent 和工作台区分无结果、部分成功与外部服务失败。ReAct、V2 和 Supervisor 均收敛为只推荐/加入监控，不执行供应商准入；流式适配器可正确输出边界提示。

验收记录：后端寻源、V2、Supervisor 和 Agent E2E 定向回归通过；后端非集成回归 511 项、PostgreSQL/MongoDB/Redis 集成回归 228 项通过；外部候选证据来源、候选 ID、阶段失败状态和准入边界均有覆盖；前端候选卡片展示匹配/核验原因、来源、更新时间、官网和联系方式，lint、类型检查、Vitest 50 项和生产构建通过。

验收：询问“推荐某品类供应商”时，结果可解释、可追溯；本地无结果时能够继续外部发现；不合格候选不会冒充正式供应商。

### Task 4：完善风险监控链路（P1）

- [x] 支持从当前对话引用的单个或多个供应商直接进入风险、ESG、舆情和合规分析。
- [x] 风险结果统一包含维度、状态、等级、证据、更新时间、限制和置信度。
- [x] 对关键证据缺失、数据不可用和身份不确定的情况转为人工复核。
- [x] 支持通过人工确认创建加入监控操作；暂停和恢复监控任务待后续监控策略配置完成后实施。
- [x] 风险事件和评估保留历史版本，不覆盖既有结论。

实施记录：风险快照追加 `snapshot_id`、单企业 `snapshot_version`、`previous_snapshot_id` 和 `scoring_version`；新增只读历史查询接口，供应商画像风险页展示版本、评估时间、评分和评分体系。既有风险趋势和告警追加模型保持兼容。

验收记录：后端风险快照/API 定向测试 8 项通过；前端 9 个测试文件、50 项通过，Lint、TypeScript 检查和生产构建通过。真实数据库集成测试未在本阶段执行。

验收：用户说“对这两家做风险、ESG 和舆情分析”时，Agent 能复用上下文中的两家供应商，不再要求重复输入名称。

### Task 5：升级 Agent 工作台与结果卡片（P1）

## 5. 执行规则

- 每个阶段最多 1 次实现和 1 次复核。
- 同一问题最多修复 2 轮，仍失败则标记为阻塞，不继续无限重试。
- 数据库不可用时立即停止集成测试，改做不依赖数据库的单元测试并记录阻塞。
- 子任务只在完成、失败或阻塞时汇报，不逐次播报等待过程。
- 每 30～60 分钟进行一次阶段汇总。
- 各任务保持独立，避免形成无限扩张的长任务；Task 14、Task 15 等历史任务不重新合并回本计划。

## 6. 完成标准

本计划完成需同时满足：

- 飞书三表可以只读同步，供应商代码、内部 ID 和来源记录稳定映射。
- 推荐链路按“历史/本地 → 飞书 → 外部发现”执行并可解释。
- 风险分析能够复用多轮对话中的供应商引用，并准确标记证据不足。
- Agent 不执行供应商准入，不产生未经确认的业务写入。
- 前端结果卡片能够展示来源、更新时间、官网和联系方式。
- E2E 回归集覆盖推荐、风险、多轮引用、证据不足和人工确认场景。
- 相关问题日志、验证记录和提交信息完整。
