# 第三阶段 3C：Delivery 与跨进程对账 Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans 原地实施。用户已授权开始 3C；基线 c89e9b9a。

**Tech Stack:** FastAPI、psycopg2、MongoDB、Redis pub/sub、React/TanStack Query、pytest/Vitest；未新增依赖。

**Goal:** 把 Outbox 投递从 API 进程迁到独立 delivery worker；业务事件通过 Redis 共享分发到所有 API worker，再由本地 WebSocket 推给浏览器；前端在事件和重连时统一失效查询。

**Architecture:** PostgreSQL Outbox 仍是事实源。delivery worker 复用现有 `claim_events`、消费者幂等和死信/重试；事件发布成功后写共享失效消息。API 进程启动一个 Redis 订阅线程，只向本进程的 WebSocket 连接广播；前端收到事件或重连后读取最新持久化状态。

**Spec:** `docs/superpowers/specs/2026-10-19-durable-harness-evolution-design.md` §6.3、§6.4。

## Global Constraints

- Outbox 事件丢失不可接受；共享分发丢失不能造成数据丢失，只能造成一次性 UI 失效延迟，重连必须对账。
- 通知/投递按至少一次设计；消费键幂等；未知外部送达结果保留待对账，不盲目重发。
- Delivery worker 独立入口；API 默认托管投递，部署独立角色时通过显式开关关闭 API 投递，避免双 owner。
- 不改已有 REST/SSE 返回结构；不删除现有测试；service 层不引入 LangGraph。
- 前端统一 TanStack Query 失效；WebSocket 事件与重连都必须走到同一套 key 映射。
- 真实 PG/Redis 测试使用独立库/测试范围；不清理共享开发库。

## 实施记录（2026-10-22）

- API 默认仍托管 Outbox；`DELIVERY_ROLE_ENABLED=false` 时 API interval 只更新积压指标，独立 `app.workers.delivery` 才能领取。`OUTBOX_WORKER_ENABLED=false` 在两种角色中均停止消费，业务仍可入队。独立 worker 在 API 角色开关未关闭时拒绝启动。
- Delivery 使用现有 PG SKIP LOCKED/lease、消费键与重试/死信；SIGTERM/SIGINT 停止下一批，进程最多 30 秒排空，Compose grace 35 秒。未完成记录留待租约到期接管。
- Outbox 成功提交发布状态后才发失效提示。提示仅含事件名和空数据，业务读取重新经过 API 权限校验；分发失败不回滚已成功投递。
- 风险/预警/舆情/主动分析统一经共享总线广播，定向消息保留 open_id 范围；None 表示公开提示，空列表表示无人可见。Redis 订阅 ACK（含重连）发 `realtime_resync`，即使 WS 本身未断开也能对账。
- API 每进程一个订阅线程，只有该线程关闭 PubSub，避免跨线程 close/reset 竞争。WS 握手重新检查当前用户存在且活跃，身份查询在线程中执行。
- 前端 Layout 统一订阅事件与连接成功回调，失效列表、评估、Agent、通知及监控风险/复核/身份详情缓存；旧 socket 的迟到消息被拒。
- 独立模式通知：PG notification_dispatches + Outbox 原子入队，目标/收件人/事件指纹 24h 去重；SENDING 在调用前持久化，成功 SENT、明确失败 FAILED、撤权 CANCELLED；超时或调用中进程退出转 NEEDS_REVIEW，禁止自动重发。通知和投递审计按 PG 单调整数 version 投影，避免 Mongo 毫秒精度导致迟到状态回退。
- 正式供应商收件人只消费当前责任快照；撤销后不回退历史 owner。外部目标仍保留 owner 规则。
- API 单条已读兼容 ObjectId/UUID；通知列表剔除内部版本字段，原 REST/SSE 结构保持。

## 真实进程证据与边界

测试范围为服务器 `delivery_stage3_test`（PG/Mongo）与 UUID 隔离 Redis channel；只删除用例自己的 UUID 记录。

1. 两个独立 Uvicorn API 进程复用生产路由、JWT/cookie 鉴权和 WSManager，测试生命周期仅负责订阅，跳过重复 DDL/cron。第三进程 publish 一次，两端各收到一次；关闭其中一个订阅连接后，WS 保持连接并收到 resync。
2. Delivery 在 Mongo 投影完成、消费标记前被 SIGKILL，新的独立进程接管；业务投影仅一条，消费标记一条，事件完成。
3. 两个 delivery 进程同时争抢一个事件，仅一个消费标记和一个业务投影。
4. 通知 sender 在 SENDING 边界后被 SIGKILL，新 delivery 不再调用提供方，转 NEEDS_REVIEW。提供方均为本地替身，未真实外发通知。

- 新 notification_dispatches DDL 需要先初始化；版本化独立迁移/发布失败关闭属于 3D，本包没有给运行角色增加隐式 DDL。
