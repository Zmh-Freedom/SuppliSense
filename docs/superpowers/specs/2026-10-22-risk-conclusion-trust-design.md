# 风险结论可信度：渐进重构路线与首个交付设计

日期：2026-10-22

设计基线：88954645；包含当前工作区的产品评审记录。

状态：总体路线及本文设计已获用户确认（2026-10-22）；交付 A 于 2026-10-23 完成实现与验收，B/C 待独立设计实施。

关联问题：ISS-20261022-016、017、018、023、025、027、028。

## 1. 已确认的目标与边界

用户已选择“保留现有架构、逐步统一业务规则、按用户流程交付”：先保证风险结论可信，再保证采购事项能处理完，最后扩展分析能力。

服务对象仍是采购分析师与科室经理。第一阶段应让用户知道：分析的是哪个主体和范围、哪些事实有效、指标如何计算、结论有哪些限制，以及能否复现当时的判断。

继续使用模块化单体、FastAPI、React、现有数据库分工及唯一只读 Harness；写动作继续通过现有审批边界。业务规则保持框架无关。已有公开 API 返回结构和 SSE 事件格式保持兼容，历史评估和测试保留。

本设计不包含采购事项系统、经理审批策略重做、首页重排、新外部数据源采购、预测模型训练、微服务拆分或全量物料/工厂风险模型。它们按后续独立交付推进。

## 2. 当前实现与应复用的基础

| 当前实现 | 已有能力 | 本轮处理方式 |
| --- | --- | --- |
| `backend/app/domains/risk/assessment_service.py` | 稳定主体、评估身份、采集与冻结边界 | 保留，后续报告绑定已有评估 |
| `assessment_contracts.py` / `assessment_evidence.py` | 证据状态、哈希、来源时间、查询回执 | 复用语义，不另建证据状态体系 |

| `risk_contract.py` | Harness 的能力与维度契约 | 承载指标语义所需的内部约束 |
| `operational_risk_service.py` | 正式供应商、真实且合格快照、最新月份、缺失返回空分 | 修正指标标准化与汇总，收紧正式评级条件 |
| `tools_risk.py` / `tools/evidence.py` | 领域结果转为 Evidence / Claim | 让可核验指标生成 Claim；不能仅因服务执行成功就形成完整风险结论 |

飞书交易标准化当前包含收货、结算、物料、组织、单位等字段，并保留 `raw_fields`；质量合格率、准时率及其专用统计分母尚未成为规范化字段。服务支持某些字段不代表真实同步已具备这些数据，不能用直接构造 Mongo 文档代替数据接入验收。

## 4. 交付 A 的用户行为

采购员问“查看甲供应商的质量和交付情况”时：

1. 沿用 Harness 与现有工具执行政策，确定主体并检查访问范围。
2. 读取最新月份的真实、已校验交易快照，按已知来源契约识别指标。
3. 有合法指标时给出指标、月份及限制；不能计算汇总时明确原因。
4. 没有已确认且适用的评级政策时，不输出正式风险分和高/中/低等级。
5. 聊天事实、证据卡及历史回放使用同一指标含义；不能因指标路径名为 `risk_score` 就套用企业安全分阈值。

示例：来源明确标识 `percent` 的合格率 95.2，应标准化为 0.952 并显示“合格率 95.2%”。没有评级政策时显示“已取得指标，风险等级待确认”，不显示“低风险”。资料缺失与政策缺失分别解释，不能把已有指标一并丢弃。

## 5. 指标契约与计算规则

### 5.1 内部契约

在 `domains/risk` 内建立小型、框架无关的指标契约与纯计算函数；优先扩展 `risk_contract.py` 的语义边界，计算实现独立放置，避免继续扩大一个服务函数。

内部结果至少区分：指标名称、原单位、规范单位、数值、统计周期、分子/分母含义、数量单位、业务范围、来源记录标识、来源时间、契约版本、可计算状态、限制原因。上述为内部对象要求，不直接向旧 API 或 Claim 模型添加字段。

已有 `Claim.dimension`、`fact_path`、`unit` 和 `evidence_refs` 足以承载首轮展示；来源明细留在现有证据承载能力中。需要新增公共表达能力时另设版本化契约，不偷偷扩大原响应结构。

### 5.2 单位与非法值

- 单位来自明确的来源字段契约或显式单位标记，不通过“数值大于 1”猜测百分数。
- ratio 必须在 0–1；percent 必须在 0–100，转换后按 ratio 计算。
- 缺少已确认单位的旧别名数据，只作为未标准化来源事实，不形成可计算率或正式等级。
- 拒绝布尔值、NaN、无穷值、非法字符串、负数量和越界比例。不能截断越界值来产生零风险。
- 同一来源行多个别名提供不同数值时标记冲突，不按别名顺序静默取第一个。
- 零分母是不可计算；数值 0 在合法分母和来源条件下仍是有效观测，不能被当作缺失。

### 5.3 汇总与分母

- 已确认同一统计口径、同周期、同计量单位且不重叠的分子与分母分别求和，再计算比率。
- 不对数量取均值；不对不同样本量的比例直接取算术平均。
- 质量合格率只能使用检验口径的分母。收货数量只有在来源契约明确证明等于检验数量时才能作为权重。
- 准时率按来源明确的订单行、批次或数量口径计算，不能把“延期数量/订货数量”自动解释为按单准时率。
- 不良率不再除以收货数量。仅当其含义是同一检验总体中互斥且完备的不合格占比时，才允许使用 `1 - 不良率` 推导合格率；缺陷次数率不适用该公式。
- 多行只有比例、没有可验证权重时不生成综合比例；保留各来源事实和“无法汇总”限制。单行已发布汇总指标可作为该来源口径的指标展示，不能扩大到其他范围。
- 来源记录可唯一识别时去重；相同标识、不同内容视为冲突。标识或范围不足以排除重叠时，不进行数量汇总。
- 混合物料/基地/组织、混合单位及同月明细与汇总并存时，只有来源契约证明可合并才汇总。本轮不通过创建新的物料风险体系解决它，不能证明时返回范围不足。
- 最新月份异常时报告该月份问题，不悄悄回退旧月形成当前正常结论；月份格式必须合法。

### 5.4 评级政策

企业安全评分继续按已冻结的政策运行。质量和交付的现有 30/60 分界缺少业务确认，不作为首轮正式评级依据。

交付 A 的默认行为为：没有已确认的质量/交付政策时，`risk_score` 和 `risk_level` 使用现有允许的空值；有效指标仍输出，`assessment_status` 沿用现有 `partial` 表达有限结论。完全没有有效指标时沿用 `missing_data`。服务及工具说明必须写明差异。

正式评级启用需要另有可审阅政策记录，包含适用维度/范围、阈值边界、样本要求、有效期、版本和确认依据。当前无该记录，不填入臆造阈值，也不以演示数据通过作为启用依据。业务阈值尚未确认不会阻止交付 A 的安全收口与指标展示。

## 6. 工具、证据与前端

### 6.1 工具适配

`tools_risk.py` 继续调用领域服务并经共享证据适配器输出。调整质量/交付的 Claim 白名单，使存在于证据中的标准化指标可独立形成事实 Claim；空分数不得形成评分 Claim。

使用证据内实际存在的路径，不仅修改 `claim_fields` 就声称接通。现有运营证据的 `facts` 主要含指标，必须验证每个输出 Claim 都能解析到同一 evidence 引用中的值。不得靠复制顶层评分来绕过证据验证。

`tools/evidence.py` 的格式化只补齐这些指标的标签和单位，不把质量、交付和企业安全分都叫“综合风险评分”。来源观察时间与工具调用时间分别处理；缺少来源时间不能因为刚调用工具而变成当前有效。

### 6.2 展示规则

展示逻辑在现有扁平目录中抽取小型纯函数，由 `StructuredAgentResult` 调用；类型仍集中在 `types.ts`，不新建 services/store/features 目录。

处理顺序：Claim 验证状态 → 主体和维度 → 指标路径与单位 → 适用政策/等级 → 文案与颜色。

- 原始比率显示百分比与指标名，默认中性，不直接解释为风险等级。
- 安全分仅对已识别的企业安全评分契约保留其方向；不将其阈值应用于质量、交付或未知维度。
- 质量/交付历史 `risk_score` 仅能说明它是旧规则风险分；未绑定可验证政策时使用中性展示和“历史规则待核验”，不能重新授予正式等级。
- 未识别分数显示数值及“评分含义待核验”，不默认为安全分。
- 同一主体、维度和证据中有明确且受支持的等级时，才可按该等级显示颜色；冲突、部分支持或过期状态优先于绿色标签。
- 历史正文不改写。结构化回放可增加当前展示的限制说明，不把旧数字反转成新数字，也不修改原评估。

## 7. 数据接入与兼容策略

交付 A 不要求修改飞书表结构、不写共享开发库、不批量补造历史字段。现有 `raw_fields` 不是已经核验的质量/交付来源。

第一轮离线验收使用明确声明单位、口径和范围的 fixtures。真实来源没有这些字段时，真实验收应验证“准确显示未覆盖”，不能宣称正向质量/交付分析已上线。正式来源映射另以业务字段对照表验收后启用。

兼容检查按当前返回分支保留字段集合、字段类型、空值约定和现有状态集合；纠正数值与文案的含义允许改变错误结果，不保留误导性行为来追求快照测试通过。旧测试保留，涉及旧错误行为的断言需说明业务依据后更新。

不修改主评估四维政策，不迁移历史分数，不改变既有 `/api/v2/assessments` 的请求维度。新公共接口如后续需要，遵循项目现行路由规范单独设计。

## 9. 交付 A 验收矩阵

| 场景 | 必须得到的结果 |
| --- | --- |
| ratio 0.952；percent 95.2，各有明确单位 | 同一标准化结果 0.952，显示 95.2% |
| 无单位 95.2；ratio 95.2 | 不猜测、不截断、不形成零风险 |
| 不良率 0.048 与收货量 10000 | 不能再次相除；只在等价口径已证明时推导 95.2% 合格率 |
| 检验分母 100/9900，合格率 50%/100%，范围可合并 | 总分母 10000，合格率 99.5%，不是 75% |
| 上例只有收货量而无检验口径证明 | 不用收货量冒充检验分母，不产生正式综合比例 |
| 多行无权重、零分母、重复/冲突记录、混合单位 | 指明不可计算或冲突，无静默丢弃造成的肯定结论 |
| 有指标、无已确认评级政策 | 指标可见，正式分数与等级为空，说明政策未确认 |
| 无质量/交付字段 | 保持缺失状态，不影响已具备的企业安全评估 |
| 企业安全分与质量/交付旧风险分同为 90 | 不因字段同名得到同一个安全判断；旧运营分中性显示 |
| 质量旧分 4.8、交付旧分 90、未知维度分数 | 不套用企业安全分 40/70 阈值；有清楚的限制文案 |
| 实际工具结果 → EvidenceLedger → Harness Answer → React 组件 | Claim 有对应事实，数字/单位/限制一致；不只执行抽取出的函数 |
| 旧 API 与 SSE 兼容 | 返回结构与事件集合不变，已有缺失/权限/审批行为保持 |
| 非本人范围、同名不同主体 | 不因新指标路径扩大访问范围或混合主体 |

执行方法：先把已有反例变成业务回归，再修复；纯计算测试、服务/工具契约、Agent E2E 和组件测试分层验证。对应专项通过后执行必要的后端离线回归、前端测试、类型检查、lint 与构建。无需为文档设计运行应用测试。

真实浏览器验收至少覆盖有指标无政策、来源缺失、历史结果回放三条路径；没有真实正向来源时使用明确标记的隔离验收数据并说明限制。集成测试仅使用服务器独立测试库和独立 Redis 范围，禁止清理 `sra`、`tianyancha`。

## 10. 后续交付的硬约束

以下约束防止后续独立设计偏离目标，不代表其详细方案已经批准。

- B / 016：样本不产生正式命中或清白结论；主体模糊匹配仅为待核验线索。旧 `clean: bool` 无法表达未知，必须在 B 设计中明确兼容入口的不可用响应与新状态契约；不能以 `false` 冒充已命中，或因为缺源让整张供应商画像不可用。
- B / 023：复用来源观察时间、采集时间和版本化有效期；覆盖摘要与下一步建议共同消费有效性，不能只给日期加徽标而保留“完整可用”。
- B / 025：规则预警不称为校准概率；相同历史分数不算持续下降，跨规则版本的分数不能直接比较；模拟缺少依赖输入时不输出“影响可控”。
- B / 027：一般诉讼与劳动纠纷分开，财务代理信号与已证实环境事实分开；每维证据不足不能被总体有数据掩盖。
- C / 028：导出按不可变评估身份取数，页内内容与报告使用相同结论；明确生成时间和业务截至时间。未进入冻结评估的补充模块不得拼入并伪称同版，需显式标注独立来源版本或暂不导出。
- C：历史版本保持原貌，权限按访问时的责任范围重验；不能通过报告下载绕过当前访问控制。报告展示无财报不推断非上市。

## 11. 发布与完成定义

按 A → B → C 分批提交与验收；每批独立记录问题关闭证据。A 不涉及生产数据迁移、自动刷新、通知外发或新付费外呼。

回退应保留“未知不解释为安全”的边界。若新展示或计算不可用，降级为指标不可判定，不恢复已确认会误导的旧颜色与阈值。冻结历史数据不回写。

第一阶段最终完成需同时满足：三包问题有可复核验证；活动聊天/页面/报告结论与版本一致；缺失/过期/失败/冲突的真实链路可解释；后续需要的真实数据或业务政策缺口明确列为未开放能力。测试数量通过不能代替业务验收。

本文审阅通过后，为交付 A 编写逐步实施计划；计划按“先回归、再领域计算、再工具/展示、最后端到端与兼容验收”排列，并记录执行方式。B、C 分别在其设计与验收边界明确后进入实施。
