# 供应商画像完善设计

## 目标

让供应商画像成为可行动的供应商工作台：基础信息可信、风险动作可直接执行，且风险、财务、关联、告警和变更数据可用于判断与追溯。

## 范围与优先级

### P0：行业数据完整性与关键动作

画像聚合时检查供应商主数据的 `industry` 字段。字段为空时，服务优先从已缓存的 `baseinfo` 中解析行业；没有缓存时复用现有工商查询能力获取数据。解析成功后，回写 `suppliers.industry` 并在当前响应中返回该值。解析失败不阻断画像，前端仍以 `categories[0]` 作为展示兜底。

画像页提供三项动作：编辑主数据、重新评估风险、加入或移出监控。编辑复用现有 `PUT /api/v1/suppliers/{supplier_id}`；风险评估复用现有风险评估能力；监控动作复用现有监控清单能力。所有动作完成后失效画像、供应商列表和监控清单的查询缓存。动作错误必须在页面反馈，不能影响已加载画像的阅读。

### P1：决策展示增强

财务区显示服务端可获得的历史指标趋势，至少覆盖营收、净利润和资产负债率。关联区将画像返回的关联实体渲染为轻量关系图，关联实体可跳转其已存在的画像页；没有可跳转目标时保留列表展示。

### P2：审计与告警可读性

告警区展示严重级别、发生时间和字段变化明细。变更日志优先使用画像聚合结果，避免首屏重复获取；当用户需要更多记录时调用既有分页/限制端点继续加载。

## 架构与数据流

后端保持既有分层：`domains/supplier/service.py` 负责聚合和按需行业回填，`domains/supplier/repo.py` 负责主数据持久化，API 层只负责认证、校验与异步线程包装。画像端点的响应模型保持向后兼容，只新增可选的趋势或动作所需字段。

前端的 `SupplierProfilePage` 通过 TanStack Query 获取画像。Mutation 成功后失效 `supplierProfile`、供应商列表及 `watchlist` 查询键。图表使用项目已有 recharts；关系展示复用项目已有的 `@xyflow/react`，不新增依赖。

## 错误处理

- 工商数据查询、行业解析或回写失败时记录日志并返回原始画像，不把单域失败升级为整体失败。
- 风险评估和监控动作沿用既有 API 错误响应；前端显示中文错误信息并保留原有数据。
- 关联实体无本地供应商 ID 时不生成跳转链接。

## 测试策略

- 后端单测：已有行业不查询不回写；缓存行业可回填；无法取得行业时返回类别兜底；画像动作端点的成功与失败路径。
- 前端测试：关键动作调用正确 API 并失效对应查询；无行业时显示类别兜底；告警与变更日志不重复请求首屏数据。
- 回归：运行相关 pytest 与前端类型检查/测试；若既有全量失败，单独记录与本次无关的问题。

## 约束

- 不修改既有 API 的返回字段含义或删除既有字段。
- 不增加第三方依赖。
- 同步 MongoDB/service 调用由 FastAPI 路由通过 `asyncio.to_thread()` 执行。
- 前端维持 React、TanStack Query、Tailwind 和现有 recharts/@xyflow/react 技术栈。
