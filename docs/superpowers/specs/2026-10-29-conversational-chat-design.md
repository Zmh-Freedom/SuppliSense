# 聊天回复与业务卡片设计

日期：2026-10-29
状态：待用户评审；本文是设计，不代表功能已实现或验收。

## 目标与方案

聊天以简洁、自然的回答为主，只有实际业务结果适合结构化展示时才显示卡片。用户应能先看懂答案，再按需查看依据和处理过程。问候、感谢和能力介绍不应被当作需要人工复核的分析任务。

考虑过两种方案：一是只精简现有固定模板，改动较小，但难以针对不同问题回答；二是采用自然语言回答与按需业务卡片相结合的方案。采用第二种：复用 Harness 的结构化答案、证据和现有叙述能力，前端根据实际结果展示内容，避免另建聊天执行内核。

不改变 API 返回结构、SSE 事件契约、业务工具注册、证据事实源或写操作审批机制；不以自然语言包装替代证据校验。

## 场景与展示

| 场景 | 主回答 | 辅助内容 |
| --- | --- | --- |
| 问候、感谢、询问能力 | 简短自然地回应；适当介绍可做的事 | 不展示分析卡、证据或流程步骤 |
| 一般领域知识 | 直接回答问题，标明是通用方法而非具体企业结论 | 有明确来源时可查看依据；不伪造查询记录 |
| 具体供应商查询 | 先回答用户关心的结论和关键事实，说明关键限制 | 实际有适合展示的数据时显示相应业务卡片和依据 |
| 比较、寻源或监控列表 | 先概述结果和限制 | 有可展示的实际条目时使用表格或候选卡片；空结果说明范围与条件 |
| 输入不足、数据缺失、来源失败 | 说明已知情况、缺少什么及可执行的下一步 | 根据真实原因展示数据状态，不将未知解释为低风险或发现风险 |
| 需要写入或审批 | 清楚说明拟执行操作及对象 | 保留原有审批卡片、确认及拒绝流程，不能由回答替代审批 |

混合输入如“你好，分析某供应商的风险”优先处理其中的业务请求；短回复如“好的”、企业名称或序号可能是上下文中的确认或追问，不能仅靠词面直接当闲聊，必须先结合本轮已有会话快照和待处理状态判定。

## 回答与证据

- 正文优先回答当前问题，以实际结果和经验证的 claims、evidence 为依据；不补造企业事实、数字、来源、时间或采购结论。区分未查询、查询失败、无结果与已确认空结果；缺失不是无风险。
- 可使用现有受约束的叙述能力组织自然语言，但不能改变结构化事实、状态、限制或证据引用。模型不可用、超预算或输出不符合约束时，使用由实际结果和限制构造的简洁兜底；纯问候可用本地回应，避免为简单问候依赖模型。
- 现有叙述校验不能单独证明语义忠实：需要检验关键限制是否遗漏、结论是否反转、采购建议是否有依据，以及失败和已确认空结果是否被混淆；无法通过约束时回退到结构化事实的确定性描述。卡片和依据遵循现有授权、证据有效性及来源状态；现有字段无法区分时显示未知，不推断状态。
- 当无可用数据时不展示空的业务结论卡或“0 条数据记录”占位；需要向用户解释覆盖范围、失败原因或其他限制时，仍可提供“查看依据/查询范围”入口。该入口可包含来源、时间、状态、证据及局限，按实际存在的字段展示。
- “发现风险信号”只能在有相应证据支持时显示；`needs_review` 单独只代表需要复核，不证明有信号。没有依据的通用采购建议、虚构的已完成步骤和重复的复核提示不展示。

## 交互和生命周期

- 流式响应期间展示简短、与实际状态对应的进度；正文以一个位置呈现，避免 `answer_chunk` 与 `agent_answer` 的内容重复。业务卡片以最终结构化结果为准，增量到达时平稳更新。
- 完成后进度收起为可展开的“查看处理过程”；仅根据真实事件或记录显示步骤，缺失记录不推断成功。纯对话无流程入口。失败、停止、部分完成及等待审批均显示其真实状态。
- 先核对本地缓存及服务端历史展示投影实际保存的字段，以及跨设备和重新加载的数据来源。对可恢复的数据，历史消息、刷新和实时消息保持一致；对于未保存的结构化结果或过程事件，安全降级，不承诺还原全部卡片，不假装存在证据或执行过程。
- 卡片适配窄屏，保留键盘可操作的展开控件、清晰的文本状态和可读的对比度。

## 影响范围与验收

主要涉及 Harness 的无任务分支和叙述回退、`graphs/agent_core/narrator.py` 的事实约束、前端聊天消息与 `StructuredAgentResult` / `AgentWorkflowPanel` 的展示选择。复用已有 `agent_answer`、`evidence`、`workflow_status`、`answer_chunk` 与审批事件，先核对现有数据是否足以表达各状态，禁止为适配页面擅自更改已有返回结构。

验收覆盖：问候及感谢不产生业务任务或复核提示；问候与业务请求混合、上下文确认和候选序号不被误拦截；通用咨询、带证据的风险查询、对比和寻源、无结果、部分覆盖、来源失败分别呈现正确内容；无证据时不出现风险信号或虚构完成步骤；审批确认与拒绝链路不变。检查 SSE 中间和最终状态、正文不重复、历史刷新一致性、移动端与键盘操作。模型、API/SSE 和浏览器验收分别记录真实或替身条件，不把模拟数据当作生产证据。
