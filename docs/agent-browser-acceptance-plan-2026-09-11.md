# Agent 多轮浏览器真实验收计划

## 目标

验证采购人员在真实浏览器中使用 Agent 时，能否得到与问题意图一致、基于证据、符合责任范围的数据和采购语言，并完成监控、风险评估、寻源、审批和异常处理闭环。

本轮只做真实验收和问题记录，不在测试过程中直接修改代码。发现问题后先登记到 `docs/issue-log.md`，再单独安排修复和回归。

## 判定规则

- **通过**：回答直接对应用户意图，数据范围正确，结论有证据，状态和后续动作可理解。
- **部分通过**：主结论正确，但格式、数据解释或下一步动作不完整。
- **不通过**：答非所问、停留在内部流程、虚构数据、越权泄露或任务状态错误。
- **比赛最低通过线**：P0 用例全部通过；P1 用例无阻断主流程的问题。

| 检查项 | 期望表现 | 实测结果 |
| --- | --- | --- |

| 数据边界 | 在结论附近简洁说明覆盖范围 | 待测 |

## 浏览器执行步骤

1. 确认前端、后端和登录页可访问。
2. 管理员执行 A01、A05、A06、A07、A08、A13、A23。
3. 三名采购员分别执行 A02、A04、A11、A12、A15。
4. 对同一供应商重复执行加入、批准、拒绝，验证幂等性。
5. 执行空输入、模糊名称、无数据主体、刷新页面和网络中断场景。
6. 每条用例记录用户问题、完整回答、执行详情、网络请求、日志和判定。
7. 发现问题时，先登记 `docs/issue-log.md`，再进入修复和回归流程。

## 验收记录字段

每条用例至少记录：

- 实际用户输入
- 实际 Agent 回答
- 页面截图或关键页面状态
- 是否调用预期工具
- 是否遵守责任范围
- 是否生成风险/任务/审批结果
- 是否出现内部术语或答非所问
- 判定：通过 / 部分通过 / 不通过
- 问题编号与后续修复提交
