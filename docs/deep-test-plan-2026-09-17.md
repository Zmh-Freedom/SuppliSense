# 供应商智能寻源与风险监控工作台深度测试计划

**日期：** 2026-09-17
**范围：** 前端工作台、后端 API、数据集成、权限隔离、LangGraph Harness 对话 Agent、监控审批闭环。
**目标：** 在不污染生产数据的前提下，验证采购人员从寻源、评估、比较、监控到审批的完整流程；对话部分覆盖 60 条固定问题、变体和异常输入，形成可重复执行的回归集。

## 1. 测试原则与通过门槛

- 聊天的 `auto`、`harness` 和只读旧 mode 都必须落入唯一 Harness Runtime；不得因措辞不同进入另一条活动执行路径。
- 每次对话只使用一次请求级 `execution_context`；不得跨用户、跨会话泄漏供应商、交易或审批数据。
- 每个业务结论应包含可理解的事实依据、数据来源/覆盖边界和下一步建议。数据缺失、冲突或过期时，必须降级说明，不能推断为低风险。
- 所有写操作（加入/移出监控、确认主体、创建寻源请求、生成定时报告等）都只能生成待审批动作；批准前不得写入业务数据，批准/拒绝/重复点击必须幂等。
- P0 用例 100% 通过；P1 无阻断业务闭环的问题；P2 记录体验或文案问题。性能、稳定性与安全门槛见第 8 节。

## 2. 环境、角色和数据准备

### 2.1 独立测试环境

1. 使用独立的 MongoDB、PostgreSQL、Redis 和对象存储命名空间；禁止直接在生产库执行写入用例。
2. 部署与准生产一致的 FastAPI、前端、Harness、checkpoint、外部 Provider 配置；外部 API 使用限流账号或录制响应，避免真实数据漂移导致回归不稳定。
3. 开始前执行 `/health/ready`，确认 PostgreSQL、MongoDB、Redis 与 checkpoint 四项均为 `ok`；记录前后端版本、Git commit、配置摘要及数据快照版本。
4. 浏览器覆盖 Chrome/Edge 最新版，桌面宽度 1440px 和常用笔记本宽度 1280px；至少执行一次 375px 宽度的关键阅读与审批卡检查。

### 2.2 账号矩阵

| 角色 | 账号数据范围 | 主要验证点 |
| --- | --- | --- |
| 管理员 | 全量正式供应商、全局监控 | 管理、审批、全局报表 |
| 采购员 A | 仅本人负责供应商 | 行级权限、个人监控、跨人越权 |
| 采购员 B | 与 A 无重叠的供应商 | 会话/数据隔离、反向越权 |
| 部门经理 | 本部门供应商 | 聚合可见性、非本部门隔离 |
| 无权限/失效令牌用户 | 无有效数据范围 | 401/403、前端退出与错误提示 |

### 2.3 固定测试数据

准备并标记为 `E2E_TEST` 的可清理数据，不复用真实写入对象：

- 3 家正式供应商：低风险且数据完整、存在司法/财务风险、交易数据缺失。
- 2 家同名或近似名称主体（例如“海拉”“上海海拉电子有限公司”），用于主体消歧。
- 2 家外部候选和 1 家无任何数据主体，用于未验证、无结果和降级场景。
- 至少 2 个品类及历史供应商、外部候选、无候选品类各一组。
- 可控风险快照：上升、下降、稳定、证据冲突、来源过期各一组。
- 待审批、已批准、已拒绝、已取消、已过期任务各一条；所有写入测试使用唯一 run 前缀。

## 3. 测试阶段与工作分工

| 阶段 | 工作 | 产出 | 退出条件 |
| --- | --- | --- | --- |
| T0 冒烟与基线 | 健康检查、登录、核心 API、数据/版本冻结 | 环境基线记录 | 四项依赖健康，P0 冒烟通过 |
| T1 自动化回归 | 单元、图级、API、Agent E2E、前端测试和构建 | CI 报告、覆盖率 | 现有门禁全绿，Harness 核心覆盖率不低于 80% |
| T2 Agent 离线评测 | 执行第 5 节 60 条问题及措辞变体 | JSON/CSV 评测结果 | P0 全过，指标达标 |
| T3 浏览器业务验收 | 用真实 UI 完成寻源、风险、审批、恢复闭环 | 截图、HAR、录像/控制台日志 | 关键流程无阻断 |
| T4 非功能与安全 | 并发、断网、超时、权限、幂等、可观测性 | 压测和安全测试报告 | 达到第 8 节门槛 |
| T5 缺陷回归与签收 | 登记、修复、定向+全量回归 | issue-log、签收报告 | 所有 P0/P1 关闭或获书面豁免 |

发现问题后，先将现象、影响、根因假设、复现步骤写入 `docs/issue-log.md`，再修复；关闭时补充验证证据和关联提交。

## 4. 全功能测试清单

### 4.1 工作台与 API

- 登录、登出、令牌过期、刷新后会话恢复、错误信封和无权限跳转。
- 总览、供应商库、供应商画像、风险明细/历史、财务、司法、舆情、ESG、合规、关联图谱、告警与通知。
- 寻源工作台：历史供应商、内部库搜索、外部扩源、候选选择、来源与未验证状态、无候选/服务失败降级。
- 风险工作台：综合评分、经营/运营/宏观风险、趋势、预警、情景模拟、替代供应商、供应商对比。
- 报表：生成、下载/展示、定时任务创建、更新、失败提示与权限边界。
- API：请求参数校验、中文错误信息、超时 504、分页/筛选/排序、并发重复提交、审计记录与缓存失效。

### 4.2 Agent 与流式协议

- SSE 依次验证 `thinking`、`tool_call`、`tool_result`、`answer_chunk`、`agent_answer`、`evidence`、`workflow_status`、`approval_required`、`done`、`error` 的合法性及前端展示。
- 验证多轮指代、主体消歧、组合任务、部分工具失败、证据冲突、循环上限、取消/恢复、刷新/断线后的 `Last-Event-ID` 回放。
- 记录每轮的输入、会话 ID、可见工具调用、证据引用、回答、审批 ID、耗时、HTTP/SSE 状态和浏览器控制台错误；不要将用户输入、企业名称或 run ID 写入 Prometheus label。

## 6. Agent 判定方法与指标

| 指标 | 计算/判定 | 建议门槛 |
| --- | --- | --- |
| 意图与目标解析准确率 | 意图、供应商、品类、时间和指代全部正确的比例 | P0 100%，总体 ≥95% |
| 任务完成率 | 得到符合预期的业务答案或允许的降级结果 | ≥95% |
| 证据覆盖率 | 关键结论有相应来源/数据边界的比例 | ≥98% |
| 无依据结论率 | 无证据却给出风险/联系方式/认证结论的比例 | 0 |
| 权限绕过率 | 越权读取或写入次数 | 0 |
| 审批绕过/重复写入率 | 未批准写入或同一任务重复生效次数 | 0 |
| 澄清正确率 | 模糊主体、空输入和无效意图被正确收口的比例 | ≥95% |
| 失败降级正确率 | 工具/外部源失败时不幻觉且给出处理方式的比例 | 100% |
| P95 对话时延 | 从提交到 `done`，分本地和外部源统计 | 本地 ≤10s；外部源 ≤60s |

回答质量由两人盲评：一名业务验收人按“是否能做采购决策”判断，一名技术验收人按工具轨迹、证据、权限与状态判断；意见不一致时由测试负责人复核原始 SSE 记录。

## 7. 自动化与浏览器执行方式

1. **离线测试：** 将第 5 节写成版本化 JSONL（输入、角色、前置、期望意图、必须/禁止工具、最小证据、断言）。使用固定 LLM stub 或录制外部结果，验证解析、证据账本、答案契约、SSE 和审批状态。
2. **真实链路测试：** 在隔离环境执行 `agent_e2e_live`，只允许替换外部 LLM/Provider，不替换 FastAPI、Harness、ToolRegistry/ToolExecutor、三数据库或 PostgreSQL checkpoint。
3. **浏览器验收：** 每一类至少一条由测试人员在 UI 输入；记录截图、网络面板、控制台与 SSE。对 Q27–Q31、Q46–Q47、Q60 强制执行刷新、后退、断网重连和重复点击。
4. **API 契约：** 对正常、非法参数、缺失认证、越权、超时、并发重复请求分别断言 HTTP 状态、统一错误信封及无副作用。
5. **数据清理：** 仅按本轮 `E2E_TEST_<run_id>` 精确删除测试对象；完成前先导出审批/审计证据，绝不使用宽泛删除命令。

建议回归命令：

```bash
cd backend
python -m pytest -m "not agent_e2e" -v
python -m pytest -m "agent_e2e and not agent_e2e_live" -v
python -m pytest -m agent_e2e_live -v

cd ../frontend
npm test -- --run
npm run lint
npm run build
```

## 8. 非功能、安全和可靠性测试

- **并发与幂等：** 10–30 个并发只读查询；同一审批任务并发批准/拒绝；同一聊天请求重放。检查无重复监控、重复评分、重复报告或状态倒退。
- **韧性：** 分别模拟 LLM 超时、外部工商/新闻源超时、MongoDB/Redis 短暂不可用、SSE 断线、浏览器刷新；验证超时上限、中文可理解提示、可恢复状态与审计轨迹。
- **安全：** 未登录、过期令牌、角色越权、ID 枚举、跨会话 ID、提示注入、超长输入、特殊字符、速率限制和敏感字段最小披露。
- **可观测性：** 每个 run 可通过 trace/log/audit 关联到会话和任务；指标只使用低基数标签；错误不泄露令牌、连接串、内部堆栈或其他用户数据。
- **可用性：** 长回答分块持续可读、引用卡可打开、审批卡状态不闪烁、表格中文表头完整、错误/部分结果/加载状态可理解；浏览器控制台不得有 error/warning。

| D7 | 修复后定向回归 + 全量回归，整理度量、遗留风险和发布签收结论 |

## 10. 缺陷模板与最终交付

每个缺陷在 `docs/issue-log.md` 记录：发现日期、环境/版本、用例编号、角色与前置数据、实际输入、复现步骤、实际/期望结果、SSE/网络证据、影响、优先级、根因、修复方案、验证结果、关联提交和复发关系。

测试结束交付以下材料：

1. 用例执行表（60 条固定问题及全部变体的通过率）。
2. 自动化测试、覆盖率、性能和安全结果。
3. 浏览器截图/HAR、关键审批与审计证据。
4. 已关闭与遗留缺陷清单，以及 P0/P1 发布结论和回滚建议。
