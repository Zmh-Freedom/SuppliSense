# 供应商智能寻源与风险监控工作台｜比赛演示执行脚本

> 建议时长：5—6 分钟
> 演示重点：让评委看到 **AI 采购助手能回答什么、回答依据是什么、回答后采购人员如何继续处理**。
> 演示结构：单家供应商风险复核 → 连续追问解释依据 → 替代寻源 → 候选边界与人工控制。

---

## 一、录制前只做这 5 件事

1. 浏览器保持 1920 × 1080、缩放 100%，关闭聊天软件通知、开发者工具和无关标签页。
2. 提前登录系统，确认“采购工作台”“AI 采购助手”“寻源建议”“风险监控”均可打开。
3. 录制前新建一个空白 AI 采购助手会话；**不要**使用带有其他问题的历史会话。
4. 将下方 5 条问题复制到便签中，录制时逐条粘贴，避免输入错误。
5. 每次回答完成后停留 2 秒，再开始讲解；不朗读分数等可能随数据刷新变化的具体数值。

### 本次录制使用的固定问题

| 编号 | 输入内容 | 用途 |
| --- | --- | --- |
| Q1 | `查看一下青岛三祥科技股份有限公司的风险情况` | 展示单家供应商风险复核入口。 |
| Q2 | `风险结论主要依据哪些数据？` | 展示证据、数据覆盖和结论边界。 |
| Q3 | `这家供应商下一步建议怎么处理？` | 展示采购处置建议与人工复核边界。 |
| Q4 | `找一下安全带的供应商` | 展示历史合作、正式供应商与外部候选的寻源结果。 |
| Q5 | `外部待核验候选和正式供应商有什么区别？` | 展示候选准入边界，避免评委误解“推荐即准入”。 |

## 二、逐步录制脚本

### 步骤 1：用 20 秒说明项目解决什么问题

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 0:00—0:20 |
| 页面 | 采购工作台首页 |
| 操作 | 不点击。鼠标依次指向“风险状态概览”“早期预警信号”和“AI 采购助手”入口。 |
| 旁白 | “采购人员在寻源定点和供应商管理过程中，需要持续关注供应商风险变化。过去需要跨系统查资料、整理依据，再决定是否复核或准备替代资源。这个工作台把风险监控、AI 辅助复核和智能寻源放到一个入口。” |
| 评委应看到 | 工作台有风险总览、预警信息和 AI 采购助手入口；先建立业务场景，不急于介绍技术名词。 |

### 步骤 2：提问 Q1，展示 AI 如何完成单家风险复核

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 0:20—1:20 |
| 页面 | 点击左侧 **AI 采购助手**，新建会话。 |
| 操作 | 粘贴 Q1：`查看一下青岛三祥科技股份有限公司的风险情况`，点击发送。等待回答完成。 |
| 录屏动作 | 回答出现后，先完整展示顶部结论；再缓慢向下滚动，展示风险维度、数据来源或证据卡片。不要快速翻动。 |
| 旁白 | “采购员只需要输入供应商名称和问题。助手会汇集当前可用的财务、司法、舆情、内部交易等信息，形成风险结论，并把结论和依据分开呈现。这里不是只给一个分数，而是让采购人员看到哪些信息支撑了判断。” |
| 评委应看到 | 有明确的供应商对象、风险结论、可解释依据，以及数据未覆盖或需进一步核实的提示。 |
| 不要说 | 不要说“系统自动替代采购决策”；不要把“数据不足”解释为“没有风险”。 |

### 步骤 3：在同一会话追问 Q2，展示回答依据和数据边界

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 1:20—2:05 |
| 页面 | 保持在步骤 2 的同一会话。 |
| 操作 | 在输入框粘贴 Q2：`风险结论主要依据哪些数据？`，点击发送。 |
| 录屏动作 | 回答完成后，停在证据、来源、数据时间或数据覆盖提示附近；如有“展开依据”按钮，只展开 1 条代表性依据。 |
| 旁白 | “第二个问题不是重新检索，而是沿着同一供应商继续追问。助手会把结论拆回到依据：哪些是已有事实，哪些是风险信号，哪些数据尚未覆盖。这样采购人员可以判断结论是否足够支持当前业务动作。” |
| 评委应看到 | 对话具备连续追问能力；回答包含来源、依据或数据覆盖说明，而不是泛泛的文字结论。 |

### 步骤 4：继续追问 Q3，展示从分析到采购动作

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 2:05—2:45 |
| 页面 | 保持在同一会话。 |
| 操作 | 粘贴 Q3：`这家供应商下一步建议怎么处理？`，点击发送。 |
| 录屏动作 | 停在“建议动作”“优先级”“需补充核实的信息”等内容处。 |
| 旁白 | “风险分析的目的不是生成报告，而是支持下一步处理。助手会结合风险变化和数据覆盖提出继续观察、补充核验或进一步复核等建议。涉及加入监控、移出监控等会改变业务状态的操作，系统会进入人工确认和留痕流程。” |
| 评委应看到 | 系统输出的是可执行的采购跟进方向；最终业务动作仍由人员确认。 |

### 步骤 5：新建会话提问 Q4，展示智能寻源结果

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 2:45—3:50 |
| 页面 | 点击 **+ 新对话**，保持在 AI 采购助手。 |
| 操作 | 粘贴 Q4：`找一下安全带的供应商`，点击发送。 |
| 录屏动作 | 回答完成后，先展示候选分组和候选名称；再展开或停在 1 家历史合作候选、1 家外部待核验候选上，展示匹配品类、主营产品和来源。必要时切到“寻源建议”页面补充展示候选卡。 |
| 旁白 | “当现有供应商需要复核，或者采购需要准备替代资源时，助手可以继续完成寻源。结果会区分历史合作供应商、正式供应商和外部待核验候选，并展示匹配品类、主营产品和来源信息，帮助采购员先建立候选池。” |
| 评委应看到 | 寻源不是只返回一串企业名称，而是按候选来源和核验状态分层；候选信息带有业务判断所需的产品和来源说明。 |

### 步骤 6：追问 Q5，强调业务边界和可信性

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 3:50—4:35 |
| 页面 | 保持在步骤 5 的寻源会话。 |
| 操作 | 粘贴 Q5：`外部待核验候选和正式供应商有什么区别？`，点击发送。 |
| 录屏动作 | 回答完成后，停在“外部待核验”“需人工核验”或相近的边界说明上；随后切换到“供应商库”，展示正式供应商只读标识。 |
| 旁白 | “系统把外部候选定位为寻源线索，而不是已准入供应商。外部候选还要经过资料对应确认、资质、质量、价格和产能等业务核验；供应商库中的正式供应商则来自现有主数据。这一边界保证了 AI 推荐不会绕开采购准入流程。” |
| 评委应看到 | 外部候选与正式供应商有清楚的状态区分；系统能说明自身不能替代的人工环节。 |

### 步骤 7：用风险监控页收尾，串起完整闭环

| 项目 | 执行内容 |
| --- | --- |
| 时间 | 4:35—5:10 |
| 页面 | 切换至 **风险监控**，任选一个已有监控对象打开详情。 |
| 操作 | 指向“风险变化”“数据覆盖”“下一步”以及“复核任务闭环”区域；不点击“移除”“再次发起复核”等写操作。 |
| 旁白 | “这条链路最终沉淀回风险监控：采购员可以持续查看风险变化、数据覆盖、复核依据和处理记录。项目的价值在于把发现风险、解释风险、提出动作和准备替代资源连接起来，减少重复检索，同时保留人工确认和全过程留痕。” |
| 评委应看到 | 从 AI 问答到风险监控的业务闭环，而不是独立的聊天机器人。 |

## 三、回答不稳定时的处理方式

| 情况 | 现场处理 |
| --- | --- |
| 回答生成较慢 | 静音等待或在后期剪掉等待时间；不要重复发送问题。 |
| 回答中出现“数据不足” | 正常展示，并补充一句：“系统把缺口明确标出来，避免把未覆盖误判为风险稳定。” |
| 回答内容与预演略有不同 | 按“结论、依据、数据边界、下一步”四个角度讲解，不读固定数值。 |
| 外部候选暂未返回 | 展示历史合作或正式供应商候选，并说明外部数据需以当次数据源可用性为准；不要临时更换陌生物料。 |
| 某条问题异常 | 使用预演时保留的同场景会话或已录好的备用片段；不要在录制中改动监控名单、审批状态或主数据。 |

## 四、录制完成前检查

- 是否完整展示了 Q1—Q5 中至少 4 条问题，以及“单家复核—连续追问—寻源—边界说明”的主线；
- 每个 AI 回答是否都展示了至少一个可解释依据、数据覆盖提示或下一步建议；
- 是否明确说明外部候选不是正式供应商、数据不足不是无风险；
- 是否避免了输入账号密码、接口地址、密钥、未脱敏个人信息；
- 是否未执行“加入监控”“移出监控”等写操作；
- 项目名称统一为“供应商智能寻源与风险监控工作台”，功能名称统一为“AI 采购助手”。

## 五、可直接朗读的完整演示稿

> 使用方式：方括号内为录屏操作，不需要朗读；其余文字可直接作为旁白。正常语速约 5 分钟。

### 0:00—0:25｜项目开场

【画面：采购工作台首页，先停留 2 秒；鼠标依次指向风险概览、预警区域和 AI 采购助手入口。】

大家好，我演示的项目是**供应商智能寻源与风险监控工作台**。它服务于采购寻源定点、供应商管理和供应保障等场景。

在实际工作中，采购人员不仅要寻找合适的供应商，还需要持续关注现有供应商的经营、履约和合规风险。当风险出现变化时，往往还要进一步核对信息、判断影响，并在必要时准备替代资源。过去这些工作依赖跨系统查询和人工整理，信息分散、处理链路长，也不利于后续追溯。

这个工作台将风险监控、AI 辅助复核和智能寻源放在同一个入口。接下来我重点演示 AI 采购助手如何围绕一个真实采购问题，完成风险分析、连续追问和替代寻源。

### 0:25—1:25｜问题一：查看单家供应商风险

【画面：点击左侧“AI 采购助手”，点击“+ 新对话”。在输入框粘贴 Q1：`查看一下青岛三祥科技股份有限公司的风险情况`，点击发送。等待回答完成。】

首先，我以“青岛三祥科技股份有限公司”为例，直接询问它当前的风险情况。

采购人员不需要先分别进入财务、司法、舆情或内部交易系统查找资料，只需要输入供应商名称和问题。AI 采购助手会根据当前可用数据，组织对应的风险信息并给出结构化回答。

【画面：回答完成后，停在顶部结论区域。】

这里可以先看到本轮风险结论和当前需要关注的重点。对于采购人员而言，结论只是入口，更重要的是能够继续看到这个结论基于什么信息形成。

【画面：缓慢向下滚动，展示风险维度、风险依据或证据卡片。】

系统会将财务、司法、舆情、内部交易等可获取信息，按照风险维度和证据进行呈现。这样采购人员不只是看到一个风险标签，还能判断具体是哪些风险信号需要关注。

如果某类数据暂未覆盖，系统会明确标记数据不足或未覆盖。这里的设计原则是：数据不足不等于没有风险，采购人员需要根据提示决定是否补充核验。

### 1:25—2:10｜问题二：追问风险结论的依据

【画面：保持在同一会话。在输入框粘贴 Q2：`风险结论主要依据哪些数据？`，点击发送。】

接下来，我在同一个会话里继续追问：这个风险结论主要依据哪些数据？

这一步展示的是助手的连续对话能力。系统能够承接前面已经识别的供应商和风险分析上下文，不需要采购人员重复输入企业名称，也不会把新的问题当作一个孤立查询。

【画面：回答完成后，停在数据来源、证据、数据时间或覆盖范围说明处；如有展开按钮，只展开一条。】

回答会进一步说明结论所依据的数据类型、相关风险信号和数据覆盖情况。采购人员可以据此区分：哪些信息是已有事实，哪些是系统根据事实形成的风险判断，哪些信息仍需要人工补充确认。

通过这种方式，AI 的回答从“给出结论”延伸到“说明依据”，帮助采购人员更快完成核对，而不是黑盒式地接受一个结论。

### 2:10—2:55｜问题三：追问下一步采购动作

【画面：仍保持同一会话。在输入框粘贴 Q3：`这家供应商下一步建议怎么处理？`，点击发送。】

在了解风险结论和依据后，采购人员更关心的是：下一步应该怎么处理。

【画面：回答完成后，停在建议动作、优先级、待核验事项等位置。】

系统会结合风险变化和数据覆盖情况，给出继续观察、补充核验或进一步复核等建议。这些建议的作用，是帮助采购人员确定处理优先级和待补充的信息，而不是替代采购人员作出业务决定。

对于加入监控、移出监控等会改变业务状态的操作，系统会通过人工确认和过程留痕来控制。也就是说，AI 负责归集信息、提出建议，最终的业务动作仍然由人员确认执行。

### 2:55—4:05｜问题四：从风险复核延伸到智能寻源

【画面：点击“+ 新对话”。在输入框粘贴 Q4：`找一下安全带的供应商`，点击发送。】

当供应商需要重点复核，或者采购需要提前准备替代资源时，工作流可以自然延伸到智能寻源。

这里我直接询问安全带供应商。系统会根据采购需求检索已有合作信息和可获取的外部候选信息，并将候选按来源和当前状态分层展示。

【画面：回答完成后，先展示候选分组和候选名称；随后停在一条历史合作或正式供应商候选上。】

对于已有合作或正式供应商，采购人员可以快速查看它与需求的匹配信息，例如匹配品类、主营产品和来源。

【画面：展示一条外部待核验候选，必要时切换“寻源建议”页展示候选卡。】

对于外部候选，系统同样会展示匹配线索和来源，但会明确标识为“外部待核验候选”。这类信息用于帮助采购人员建立候选池，后续仍需要开展资料确认、资质、质量、价格和产能等业务核验。

### 4:05—4:40｜问题五：说明候选边界

【画面：保持在寻源会话。在输入框粘贴 Q5：`外部待核验候选和正式供应商有什么区别？`，点击发送。】

为了避免把 AI 推荐误解为供应商准入，我继续追问外部待核验候选和正式供应商的区别。

【画面：回答完成后，停在“外部待核验”“需人工核验”等说明处；随后切换供应商库，展示“正式供应商”“只读主数据”标识。】

系统的边界是清楚的：外部候选是寻源线索，不等同于已经准入；供应商库中的正式供应商来自现有主数据。AI 可以帮助缩短信息收集和初筛时间，但不会绕开采购准入和人工决策流程。

### 4:40—5:10｜闭环收尾

【画面：切换到“风险监控”，打开已有监控对象详情；依次指向风险变化、数据覆盖、下一步和复核任务闭环。】

最后回到风险监控页面。通过这里，采购人员可以持续查看供应商的风险变化、数据覆盖、复核依据和处理记录。

供应商智能寻源与风险监控工作台的价值，不是单独提供一个聊天工具，而是把风险发现、风险解释、采购跟进和替代寻源连接为一条可追溯的业务链路：风险变化能够被及时发现，分析依据能够被核对，后续处理能够被跟进，替代资源也能够被提前准备。

后续，项目还将逐步接入质量、物流和零件级数据，并与 DICP 采购一体化平台衔接，进一步提升采购风险识别和处置效率。我的演示结束，谢谢大家。
