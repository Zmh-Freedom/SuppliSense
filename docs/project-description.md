# SuppliSense 项目说明书

**项目名称：** SuppliSense 供应商智能寻源与风险监控工作台
**当前版本：** 0.3.0
**文档日期：** 2026-09-11

## 1. 项目概述

SuppliSense 面向采购团队，提供供应商风险复核、风险监控、智能寻源、供应商画像和风险通知能力。系统将多来源数据转化为带证据、带数据边界、可安排后续动作的业务结果，降低采购人员在供应商识别、风险核查和候选搜寻上的信息整理成本。

项目定位是“供应商智能寻源与风险监控工作台”，不是供应商准入系统、供应商主数据系统或自动采购决策系统。

## 2. 建设目标

### 2.1 业务目标

- 聚合外部企业风险、财务、舆情、合规和内部采购数据；
- 支持采购人员用自然语言提出风险复核和寻源问题；
- 让每个重要结论都能追溯到工具结果、数据来源和覆盖边界；
- 以责任范围隔离供应商数据，满足采购员、科室经理和管理员的差异化访问；
- 对加入监控等写操作保留人工审批和审计链路；
- 区分历史合作供应商、正式供应商和外部待验证候选，避免误把线索当成准入结果。

### 2.2 产品目标

系统围绕三个问题提供服务：

1. 我负责的供应商本轮发生了什么风险变化？
2. 结论依据是什么，还需要向谁补充或核实什么？
3. 某个物料或品类有哪些历史供应商和可验证的外部候选？

## 3. 产品范围

| 模块 | 说明 |
| --- | --- |
| 采购助手 | 自然语言查询、风险复核、范围查询、趋势/舆情/报告请求、证据化结果展示 |
| 风险监控 | 主体识别与确认、监控对象、风险快照、趋势、告警和采购复核任务 |
| 智能寻源 | 历史供应商召回、正式供应商匹配、外部候选发现与主体/风险核验 |
| 供应商库 | 飞书正式供应商只读快照、供应商列表和供应商画像 |
| 风险与合规 | 工商、司法、经营异常、制裁、ESG、舆情、财务和商务风险辅助分析 |
| 通知与审计 | 站内通知、实时推送、飞书逐人通知、投递重试、操作审计和运行事件 |
| 数据同步 | 飞书多维表格供应商、责任分配和交易快照的按配置同步 |

## 4. 明确不在范围内

- 自动供应商准入、自动淘汰或自动切换供应商；
- 自动写回飞书正式供应商主数据；
- 以收货记录数直接推断零件数量、交付能力或采购金额；
- 在没有可验证证据时生成确定性低风险/高风险结论；
- 用名称相似度代替企业主体确认；
- 让 Agent 绕过责任范围访问其他采购员或科室的数据；
- 无人工审批地执行监控清单等业务写操作。

## 5. 用户与权限模型

供应商责任分配以飞书责任表为来源，并同步为 PostgreSQL 本地快照，运行时按当前账号过滤。

| 角色 | 权限原则 |
| --- | --- |
| 采购员（purchaser） | 只能访问本人负责的正式供应商、监控对象、风险快照和告警 |
| 科室经理 | 可访问所属科室采购员负责的数据，用于团队复核和汇总 |
| 管理员（admin） | 可访问全量演示数据和运维能力，负责用户、同步和审计管理 |

正式供应商原则上只分配给一名采购员。工具层和服务层均应执行责任范围校验；缺少当前用户身份时采用 fail-closed 策略。

## 6. 核心业务流程

### 6.1 风险监控流程

```text
输入企业信息
  → 搜索主体候选
  → 用户确认主体
  → 创建稳定 ID 的监控对象
  → 汇集多源证据
  → 生成风险结论、证据和数据边界
  → 创建复核任务
  → 写操作人工审批
  → 执行并回写结果、证据与风险快照
```

### 6.2 智能寻源流程

```text
输入物料/品类
  → 召回历史零件—供应商关系
  → 匹配飞书正式供应商快照
  → 补充外部待验证候选
  → 进行主体与风险核验
  → 按来源和待核验项展示
```

### 6.3 聊天运行流程

活动聊天统一进入 LangGraph Harness Runtime。每轮请求加载一次执行上下文，生成任务矩阵，调用统一工具执行器，收集证据与 Claim，最后生成结构化 AgentAnswer。运行过程通过 SSE 输出；服务端持久化事件后支持按 `run_id` 断线回放。

涉及写操作时，使用持久化 Agent Supervisor 作为人工审批兼容入口。历史 ReAct、Plan-Execute、Parallel 等图仅用于定向回归，不是活动聊天的执行内核。

## 7. 技术架构

```text
React 19 + Vite 8
  ├─ Tailwind CSS 4
  ├─ TanStack Query 5
  ├─ SSE 流式聊天与断线回放
  └─ WebSocket 实时告警

FastAPI + Uvicorn/Gunicorn
  ├─ API 路由与认证
  ├─ LangGraph Harness Runtime
  ├─ Agent Supervisor / 审批恢复
  ├─ ToolRegistry / ToolExecutor
  ├─ 风险、寻源、供应商、告警和通知领域服务
  └─ 飞书同步与 APScheduler 定时任务

PostgreSQL：用户、责任快照、Session / Turn / Run / Task / Proposal、审计与控制面状态
MongoDB：业务数据、风险快照、告警、证据和展示记录
Redis：缓存、限流及运行时辅助状态
DeepSeek：意图理解与结论生成（OpenAI 兼容接口）
```

## 8. 数据源与数据流

| 数据源 | 进入系统的方式 | 主要用途 |
| --- | --- | --- |
| 天眼查 | API 调用 | 企业身份、工商、司法和经营风险 |
| 财报/财务数据 | 已配置数据接口或本地数据 | 财务指标和趋势 |
| 飞书多维表格 | 只读同步 | 正式供应商、责任分配、能力、联系人和交易快照 |
| 外部候选/网络发现 | 受限只读发现 | 智能寻源候选线索 |
| PostgreSQL | 应用写入 | 用户、责任快照、Agent 生命周期、审批和审计 |
| MongoDB | 应用读写 | 业务数据、证据、风险快照、告警和展示记录 |

系统在结果中同时保存来源、时间、覆盖状态和证据引用，避免把“无数据”包装为“无风险”。

## 10. 部署与运维

### 10.1 本地开发

依赖 Python 3.12、Node.js 20+、Docker、PostgreSQL、MongoDB、Redis。首次使用时，将 `backend/.env.example` 复制为 `backend/.env` 并填写必要配置。

```bash
./start.sh --dev

cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

cd frontend
npm install
npm run dev -- --host 0.0.0.0
```

开发环境通常访问 `http://127.0.0.1:5174`，后端就绪检查为 `http://127.0.0.1:8000/health/ready`。

### 10.2 Docker 部署

配置根目录 `.env.docker` 后执行：

```bash
./start.sh
./stop.sh
```

生产 Compose 包含 MongoDB、PostgreSQL、Redis、后端和 Nginx 前端服务。启动脚本会校验必填密码并在生产启动前尝试备份。

### 10.3 关键配置

至少需要配置：数据库密码、JWT `SECRET_KEY`、Cookie 安全属性和跨域来源。启用真实 AI、天眼查或飞书能力时，再配置对应 API Key、应用凭据和表 ID。

飞书同步由 `FEISHU_BITABLE_ENABLED=true` 开启；飞书逐人消息还需要开启 `FEISHU_USER_MESSAGE_ENABLED=true` 并确保应用拥有相应权限。

## 11. 质量保障

项目采用 pytest、FastAPI TestClient、Vitest、TypeScript、ESLint 和生产构建验证。Agent 跨图闭环测试使用 `agent_e2e` 标记，重点覆盖：

- 责任范围过滤和越权拒绝；
- 主体确认与监控对象创建；
- 工具输入/输出、证据和 Claim 契约；
- SSE 终态、断线回放和审批恢复；
- 寻源结果来源标识；
- 前端登录、核心页面加载和结构化结果展示。
